## 1. Главный тезис (TL;DR)

1. **Симуляция + массово-параллельный PPO — зрелая технология (TRL 8–9) для локомоции**, но слабо зрелая для контактно-насыщенной манипуляции с реальным sim2real.
2. **Для манипуляции в 2026 доминирует связка «демонстрации (IL) → VLA fine-tune → RL-дообучение на реальном роботе»**, а не «чистый RL в симуляторе». π*0.6/Recap и HIL-SERL — две ключевые точки доказательства того, что RL на реальном железе работает.
3. **Фундаментальная проблема для no-code: reward-функции, дизайн сред и оценка политик** — именно то, что сегодня делает эксперт. Для первых двух есть рабочие, но исследовательские решения (Eureka, VLM-reward-модели, RoboGen); для оценки — только зарождающиеся решения (real-to-sim evaluation).
4. **Железо-agnostic «нажми кнопку — робот выучил любой навык» сегодня не существует.** Реалистичный no-code продукт 2026–2027 — это узкие «рельсы»: поддержанные роботы (SO-101, Franka, UR, Unitree), поддержанные классы задач (pick-and-place, локомоция из шаблона), облачный fine-tune VLA и безопасный real-world RL с человеком в контуре (вывод).
5. **Инфраструктура RL для LLM (verl и т.п.) и для роботов сходится по абстракциям** (среда → rollout → reward → обновление политики), но единый движок «из коробки» — большая инженерная задача; общими могут быть слой оркестрации, трекинг экспериментов и reward-сервис, а не физический симулятор (вывод).

### 2.2 Что это значит для скорости обучения

- **Факт:** в MuJoCo Playground заявлены минуты на одном GPU для локомоции и манипуляции [4]. Конкретных цифр «шагов в секунду» по Isaac Lab и MJX в проверенных источниках я не получил; сравнение скоростей между симуляторами в публикуемых бенчмарках чувствительно к настройкам решателя и рендера (на примере спора вокруг Genesis [7] и оговорок ManiSkill [9]). **Не использовать рекламные FPS как основу unit-экономики** (вывод; см. 05-compute-hardware-costs.md, раздел о стоимости GPU-часа).
- **Оценка:** для типичной локомоции (квадрупед, Unitree G1/Go2 по готовому шаблону) обучение PPO занимает порядка 5–30 минут на потребительском/серверном GPU [уверенность: средняя], для ловкой манипуляции — часы–дни и значительно более хрупко.

### 3.1 π*0.6 и Recap

- **Факт:** Physical Intelligence, arXiv 2511.14759 (ноябрь 2025). Метод Recap (RL with Experience & Corrections via Advantage-conditioned Policies): сначала офлайн-RL предобучение, затем специализация через сбор данных на роботе, где используются демонстрации, человеческие коррекции и автономный опыт; обученная value-функция отбирает «выигрышные» (high-advantage) действия, политика кондиционируется на advantage. Базовая модель — VLM 5B + action expert [13][14].
- **Результаты:** на самых сложных задачах Recap более чем удваивает пропускную способность и примерно вдвое снижает долю отказов; задачи — эспрессо, складывание разнообразной одежды, сборка картонных коробок [13][14]. Вторичные источники расходятся в длительности непрерывной работы (13 против 18 часов) — смотреть первичную статью [13].
- **Оценка:** метод требует большого предобученного VLA и значимых объёмов данных на целевую задачу; это не «нажми кнопку для любого пользователя». Но идея «advantage-conditioned fine-tune из логов + вмешательств оператора» воспроизводима на открытых VLA (π0.5 и т.д.) и является естественным ядром «непрерывного улучшения» в платформе (вывод).
- **Дополнительно:** в результатах поиска всплыла работа HELP: Human-Efficient Large-Scale Robot Post-Training with Rollout Segmentation (arXiv 2607.09776, 2026) — по заголовку, про эффективность человеческого участия при постобучении; детали не проверены [уверенность: низкая] [44]. Поиск по «RL fine-tuning VLA 2026» повторить не удалось (лимит).

## 6. Автоматизация того, что требует эксперта (раздел E — ядро no-code)

### 6.1 Reward-функции

- **Eureka:** LLM (GPT-4) пишет код награды, итеративно улучшает через in-context evolutionary optimization. На 29 открытых RL-средах с 10 морфологиями превосходит человеческих экспертов в 83% задач при среднем нормированном улучшении 52%; демо — вращение ручки Shadow Hand. MIT-лицензия; требует IsaacGym Preview 4, Python 3.8 и API OpenAI [25]. **Оценка:** привязка к устаревшему IsaacGym — для продукта нужна переписка под Isaac Lab / MJX.
- **DrEureka:** добавляет LLM-генерацию безопасных инструкций к награде и распределения domain randomization (через «reward-aware physics prior»); конкурентен человеческим конфигурациям на квадрупеде и ловкой манипуляции, решает новые задачи вроде баланса и ходьбы на йога-мяче [26] (по аннотации; численные метрики не проверены).
- **VLM как reward-модель:** RoboReward (arXiv 2601.00675, январь 2026) — открытые 4B и 8B VLM-модели, обучены на 45 000 оценённых эпизодах; на реальном RL модель 8B превосходит Gemini Robotics-ER 1.5 как судью и сокращает разрыв с человеческой наградой (на задаче «open drawer» ≈ 80% против 90% при человеческой награде, база 10%). Ограничение: оценка в конце эпизода, короткие горизонты [27]. Large Reward Models (arXiv 2603.16065, март 2026) — онлайн-генерация наград для манипуляции; заявленный результат ~30 RL-итераций (вторичный источник, не проверено) [28]. В LeRobot уже есть reward-модели SARM, TOPReward, Robometer [17].
- **Вывод:** reward-слой автоматизируем уже сегодня для коротких задач с чётким визуальным критерием успеха («ящик открыт»); для многоэтапных и требующих тонкой динамики задач — нет. Отсюда продуктовое решение: пользователь описывает **критерий успеха** (текст/пример видео/клик «успех-провал»), платформа строит reward-классификатор (HIL-SERL уже использует обучаемый reward-классификатор [16]) и/или VLM-судью.

### 6.2 Генерация сред и задач

- **RoboGen** (CMU и др., ICML 2024): цикл «предложи задачу → сгенерируй сцену из Objaverse → декомпозируй на подзадачи → выбери метод (RL / motion planning / trajectory optimization) → обучи». Заявлена средняя успешность ~0.774 по 69 задачам (по alphaXiv-выжимке, не по тексту статьи); авторы признают, что массовая верификация навыков и sim2real остаются проблемой [29]. 
- GenSim и другие: поиск не проводился (лимит) [уверенность: низкая].
- **Вывод:** генерация сред из текста — исследовательский уровень (TRL 4–5); для продукта надёжнее **шаблонные среды + параметризация + загрузка пользовательских ассетов/сканов**.

### 6.3 Real2Sim (цифровые двойники)

- Real-to-Sim Robot Policy Evaluation with Gaussian Splatting Simulation of Soft-Body Interactions (arXiv 2511.04665): мягкие тела из видео + 3DGS-рендер; успех в симуляции коррелирует с реальным для политик, обученных только на реальных данных; политики с запястными камерами моделировать сложнее [30].
- Real-is-Sim (dynamic digital twin на Embodied Gaussians): 30 реальных + 30 симулированных демонстраций подняли успех с 57% до 80% [31].
- Дополнительно в выдаче: PolaRiS (arXiv 2512.16881) — real-to-sim оценка generalist-политик (только заголовок) [45]; RoboGSim [30-ряд, не проверено].
- В выдаче не нашлось подтверждения работы именно с обычной фотосъёмкой на телефон «под ключ» [30]. **Оценка: TRL 5–6, промышленных готовых сервисов «снял видео на телефон → получил физичную сцену» в моих источниках нет.**

### 6.4 World models

| Система | Что делает | Статус |
|---|---|---|
| **NVIDIA Cosmos Predict 2.5 / Transfer 2.5** | Единая flow-модель text/image/video-to-world, 2B и 14B, обучена на 200M отобранных клипов; Transfer 2.5 — sim-to-real и real-to-real трансляция видео, аугментация; веса под NVIDIA Open Model License, код Apache 2.0; на GitHub указан Cosmos 3 (2026-06-01) и перенос репозиториев [32] | Открыто, коммерчески применимо (проверять лицензию) |
| **DreamGen / GR00T-Dreams** | Дообучает видео-world model на целевого робота, генерирует «neural trajectories», извлекает действия через IDM / latent action model, обучает GR00T; гуманоид выполнил 22 новых поведения по телеоперации одной задачи в одной среде; код Apache-2.0 поверх Cosmos-Predict2 [34][35] | Исследовательский, но с кодом |
| **V-JEPA 2** (Meta) | Энкодер на >1M часов видео, V-JEPA 2-AC дообучен на <62 ч видео DROID; планирование pick-and-place на Franka в двух лабораториях без сбора данных с этих роботов и без награды [33] | Исследовательский |
| **Genie 3 + SIMA 2** | Генеративные интерактивные миры; SIMA 2 (Gemini) самостоятельно предлагает задачи и награды, работает в сценах Genie 3, не встречавшихся при обучении; релиз как limited research preview; подтверждения обучения физического робота этим способом в источниках нет [36] | Только виртуальные агенты |

**Вывод:** world models пока лучше как **генератор синтетических данных и аугментации** (Cosmos Transfer, DreamGen), чем как «симулятор для RL». Использовать их как замену физическому симулятору в RL для контактной динамики пока рискованно (оценка, TRL 4–5).

### 6.5 AutoRL и curriculum

- Прямых источников по AutoRL / автоматическому подбору гиперпараметров в этой сессии не получено [уверенность: низкая]. Поддерживающие факты: DreamerV3 и TD-MPC2 заявляют единый набор гиперпараметров на множестве доменов [39][40]; это снижает потребность в тюнинге и является **важным критерием выбора алгоритмов по умолчанию для no-code** (вывод). В Eureka есть демо curriculum (pen spinning) [25].

## 7. Что остаётся нерешённым (раздел F)

| Проблема | Состояние (факт/оценка) | Следствие для no-code |
|---|---|---|
| **Sim2real gap** | Для локомоции решён практически (MuJoCo Playground демонстрирует sim-to-real на квадрупедах, гуманоидах, руках и роботах-манипуляторах [4]); для манипуляции остаётся. RoboGen прямо признаёт sim2real барьером [29] | Для манипуляции делать упор на real-world RL / IL, симуляцию — для локомоции и предобучения |
| **Контактно-насыщенная манипуляция** | HIL-SERL решает сборку, вставку и динамические задачи, но требует человека и жёсткой настройки среды (relative proprioceptive state, reward-классификатор, Franka) [15][16] | Нужна стандартизация «рельсов» (сенсоры, захват, ограничения рабочей зоны) |
| **Sample efficiency** | Реальный RL: ~1–2.5 ч на задачу [15]; Recap: часы данных и суток работы [13] | Реальное время робота — основной ресурс; тарификация должна это учитывать |
| **Безопасность исследования** | DrEureka добавляет safety-инструкции в генерацию наград [26]; детальных источников по shielding / safe RL в этой сессии не получено [уверенность: низкая] | Обязателен аппаратный предел сил/скоростей, зона безопасности, e-stop; см. 07-risks-safety-regulation.md |
| **Reward hacking** | Специальных источников не получено; в Eureka/DrEureka подтверждается важность итераций и проверки [25][26] (оценка) | Нужен автоматический «визуальный аудит» роликов (VLM + человек) перед деплоем |
| **Обобщение** | UMI-политика ломается при смене освещения (прямое солнце) [37]; RoboReward — ограничения на длинные горизонты [27] | Показывать пользователю «область применимости» политики |
| **Evaluation** | Real-to-sim оценка растёт (2511.04665, PolaRiS), но wrist-камеры и мягкие тела проблемны [30][45]; единого стандарта нет | Отдельный модуль оценки (sim + несколько реальных прогонов с доверительными интервалами) — потенциальный moat |
| **Кросс-эмбодимент** | Открытые VLA (GR00T) имеют тег `NEW_EMBODIMENT`, но нужны данные и fine-tune [18]; Octo — на OXE [22] | Платформа должна управлять «embodiment-профилем» (кинематика, действия, камеры) |

Дополнительно: статья Robots Need More than VLA and World Models (arXiv 2606.06556, 2026) указана в выдаче, но её содержание не проверялось [46].

## 8. Референсная архитектура no-code пайплайна (раздел G)

Шкала зрелости (оценка, TRL-подобная): 1–3 идея/исследование, 4–5 лабораторная демонстрация, 6–7 прототипы, 8–9 продакшн.

| № | Шаг | Что можно автоматизировать сегодня | TRL | Открытые компоненты | Главные риски | Горизонт полной автоматизации |
|---|---|---|---|---|---|---|
| 1 | **Описание задачи на естественном языке** | LLM/VLM парсит задачу в спецификацию (цель, критерий успеха, ограничения) | 6–7 | Любой LLM; VLM-ER-модели (Gemini Robotics-ER закрыт; открытые VLM) | Неоднозначность; неверный критерий успеха | Сегодня (с подтверждением пользователя) |
| 2 | **Сканирование среды / Real2Sim** | Шаблоны сцен, ручная калибровка; 3DGS из видео — частично | 5–6 | 3DGS-пайплайны, Cosmos NuRec/Transfer [32], исследовательские Real2Sim [30][31] | Физика сцены (массы, трения) неизвестна | 1–3 года для «телефон → физичная сцена» |
| 3 | **Симуляция** | Шаблонные среды на MJX/MJWarp/Isaac Lab; добавление робота по URDF/MJCF | 7–8 (локомоция), 5–6 (манипуляция) | MuJoCo Playground [5], Isaac Lab [10], Newton [2], ManiSkill3 (ассеты NC) [8] | Лицензии; sim2real | Локомоция — сегодня; манипуляция — 1–3 года |
| 4 | **Демонстрации** | Телеоперация: лидер-фолловер, геймпад, телефон, VR; UMI-подобный сбор | 8 | LeRobot (SO101, OpenARM, xArm и др.) [17], UMI [37] | Качество данных; усилия оператора (≈2 часа на 50 демо) [38] | Сегодня |
| 5 | **IL / VLA fine-tune** | Облачное дообучение ACT / Diffusion / SmolVLA / π0.5 / GR00T на LeRobot-датасете | 7–8 | LeRobot [17], openpi [20], Isaac-GR00T [18] | Лицензии весов; GPU-стоимость (LoRA π0.5 >22.5 ГБ, полный >70 ГБ [20]); хрупкость | Сегодня для одной пары робот/задача |
| 6 | **RL-дообучение** (sim: PPO; real: HIL-SERL / Recap-подобное) | Sim-RL на шаблонах — да; real-RL — с оператором в контуре | 7 (sim-локомоция), 5–6 (real manipulation, HIL-SERL), 4–5 (Recap-подобное на открытых VLA) | RSL-RL [41], HIL-SERL [16], LeRobot RL [17], TD-MPC2 [39] | Безопасность; reward; поломка железа | Real-RL «одной кнопкой» — 1–3 года |
| 7 | **Автоматический reward** | Eureka-подобный для sim; VLM-судья для real | 5–6 | Eureka [25], RoboReward [27], reward-модели LeRobot [17] | Reward hacking; ошибки судьи; длинные горизонты | 1–3 года для надёжного покрытия |
| 8 | **Оценка** | N эпизодов в sim и на реальном роботе, статистика успеха; real-to-sim оценка | 4–6 | ManiSkill real2sim [8], PolaRiS [45] | Корреляция sim↔real; малые выборки | 1–3 года |
| 9 | **Безопасный деплой на устройство** | Экспорт на Jetson / edge, ограничители, e-stop, canary-деплой | 6–7 | GR00T на Jetson Thor ~28 Гц [18]; SmolVLA на CPU/потребительском железе [23] | Ответственность; отказоустойчивость; различия железа | Сегодня для простых роботов |
| 10 | **Непрерывное улучшение** | Сбор логов, коррекции оператора → переобучение (Recap-идея) | 4–6 | Recap (идея) [13], HIL-SERL [15] | Дрейф политики, откат версий, приватность данных | 1–3 года |

**Вывод по архитектуре:** шаги 4, 5, 9 (частично 3) можно продавать уже в 2026–2027; шаги 2, 7, 8, 10 — гибридные («авто + человек») и дают дифференциацию.

## 9. RL для не-робототехнических агентов (раздел H, кратко; подробности см. 04-beyond-robotics-use-cases.md)

- **verl** (ByteDance Seed, Apache-2.0, ~24k звёзд): PPO, GRPO, GSPO, RLOO, DAPO и др.; FSDP/Megatron для обучения, vLLM/SGLang для rollout, масштаб до 671B и сотен GPU; поддерживает multi-turn rollout с вызовом инструментов, песочницы, VLM и мультимодальный RL [42]. Это показывает, что **RLVR/GRPO-инфраструктура зрелая и open-source**.
- **Общее с роботами:** (1) абстракция среды (Gym-подобный интерфейс), (2) rollout-воркеры и распределённый learner (в HIL-SERL — actor/learner с асинхронной синхронизацией [16]; в verl — трейнер + движок rollout [42]), (3) reward как отдельный сервис (код-верифицируемый reward для LLM, VLM-судья/классификатор для роботов), (4) логирование и воспроизводимость.
- **Различия:** физика и реальное время робота против детерминированных песочниц; длительность эпизода; безопасность; стоимость сэмпла.
- **Вывод:** единый «движок» реалистичен как **единый control plane** (описание задачи → среда → reward → job → оценка → деплой) с подключаемыми бэкендами (robotics-backend: MJWarp/Isaac Lab + LeRobot; LLM-backend: verl/TRL). Попытка сделать единый вычислительный ядро — избыточна (оценка). Начинать с одного вертикального сценария и добавлять второй бэкенд после PMF.

## 10. Слабые места идеи (честно)

1. **«Любого робота и любой навык» — не решено.** Лучшие системы (Recap, HIL-SERL) требуют экспертного дизайна окружения, хорошей механики и часто операторов [13][15][16].
2. **Автоматизация reward/сред — исследовательская.** Eureka привязан к IsaacGym и API OpenAI [25]; RoboGen признаёт проблемы верификации [29]; RoboReward — короткие горизонты [27].
3. **Зависимость от NVIDIA и лицензий.** Isaac / Cosmos / GR00T — свободные, но с оговорками [10][18][32]; ManiSkill-ассеты — некоммерческие [8]; OpenVLA — Llama-лицензия [21].
4. **Нет надёжных публичных бенчмарков скорости/стоимости**; цифры вендоров противоречат друг другу [7][9]. Unit-экономику считать на собственных замерах.
5. **Быстро меняющийся ландшафт.** За год вышли Newton, GR00T N1.7, Cosmos 3, Isaac Lab 3.0 [2][10][18][32]; крупные лаборатории (Physical Intelligence, NVIDIA, Google DeepMind, Hugging Face) могут встроить «простое обучение» в собственные продукты (см. 01-market-competitors.md и 03-nocode-ml-analogs-ux.md — для конкурентов и аналогов).

## Выводы для платформы

1. **Не изобретать модель и симулятор.** Базовый слой — LeRobot (Apache-2.0, поддержка ACT/Diffusion/SmolVLA/π0.5/GR00T/HIL-SERL и десятков роботов) [17] + MuJoCo Warp/Playground (Apache-2.0) [5][12]; Isaac Lab (BSD-3) — опциональный бэкенд [10]. Преимущество — в UX, оркестрации, данных и безопасности (вывод).
2. **Первый продукт — узкие «рельсы»:** (а) локомоция по шаблонам для популярных платформ (Unitree и т.п.) через PPO в sim; (б) pick-and-place и простая манипуляция на дешёвых руках (SO-101 и аналоги) через телеоперацию → ACT/SmolVLA/π0.5 fine-tune; (в) real-RL с человеком в контуре (HIL-SERL-подобный) как премиум-фича (вывод; сверить с 01 и 06).
3. **Reward делать по принципу «пользователь описывает/показывает успех, а не пишет функцию»:** классификатор успеха + VLM-судья (RoboReward-класс [27]) + Eureka-подобная генерация для sim [25], с обязательным видеоаудитом перед запуском на железе.
4. **Модуль оценки — отдельный продукт и потенциальный moat:** автоматические серии прогонов, доверительные интервалы, real-to-sim прокси [30][45], сравнение версий политики. Рынок evaluation сейчас не стандартизован (вывод).
5. **Лицензионный комплаенс заложить в архитектуру:** запретить ManiSkill-ассеты в коммерческом пайплайне [8], отдельно проверять Llama/Gemma/NVIDIA Open Model License для каждой модели [18][20][21], не хостить Isaac Sim без юридической проверки (см. 07-risks-safety-regulation.md).
6. **Тарифицировать реальное время робота и GPU раздельно.** Fine-tune π0.5 LoRA — GPU класса 24 ГБ+ (4090), полный — 70+ ГБ (A100/H100) [20]; GR00T — 40 ГБ+ [18]; real-RL — часы времени робота [15]. Детализировать в 05-compute-hardware-costs.md и 06-business-models-pricing.md.
7. **Непрерывное улучшение (Recap-идея) — стратегическая обещание на 12–24 месяца:** логи + вмешательства оператора → переобучение политики [13]. В MVP достаточно «сбор коррекций и ручной запуск переобучения».
8. **Для не-робототехнических агентов — отдельный backend на базе verl-подобной инфраструктуры** [42], общий control plane и reward-сервис; не пытаться объединить вычислительные ядра на старте (см. 04-beyond-robotics-use-cases.md).
9. **Безопасность по умолчанию:** лимиты сил/скоростей, зона безопасности, e-stop, ограничения на real-RL; вынос в UX как «безопасный режим». Данные по safe RL в этой сессии неполные — проработать отдельно (см. 07-risks-safety-regulation.md).
10. **Следить за Newton / Isaac Lab 3.0 / Cosmos 3 / GR00T N1.7 / LeRobot** — индустриальный стандарт формируется прямо сейчас [2][10][17][18][32]; закладывать абстракцию бэкенда симуляции, чтобы не привязываться к одному.
